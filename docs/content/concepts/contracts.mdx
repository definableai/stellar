title: "Contracts: Model, Tool, hook"
description: A Model, a Tool, and a hook. Two classes with one method each, and one plain function.
---

There are three things you write yourself. All three are async, and all three
take the run.

## Model

Give it an async `invoke(run)`. It reads `run.messages` and hands back one
assistant `Message`.

```python
from core import Message, Model


class Parrot(Model):
    """Says back whatever you said."""

    async def invoke(self, run) -> Message:
        return Message("assistant", run.messages[-1].text)
```

Hand back anything else and you get a `ContractError` naming your class. For a
real provider there is a shorter road. [`ProviderModel`](/models/provider)
splits the job into `encode(run)` and `send(run, body)`.

## Tool

Give it an async `execute(run, **args)`. The run comes first, then the
arguments your schema promised, by name.

```python
from core import Tool


class Shout(Tool):
    name = "shout"
    description = "Shout a word."
    parameters = {"type": "object", "properties": {"word": {"type": "string"}}}

    async def execute(self, run, word) -> str:
        return word.upper()
```

Write `execute` as an async generator instead and the tool streams. For a
plain function, [`@tool`](/tools/functions) builds all of this from the
signature.

## Hook

A hook is a function. It takes whatever its stage hands over, and the run
after that if it leaves room for one.

```python run
import asyncio

from core import Agent, FakeModel, Message, hook

agent = Agent(FakeModel(["Hello there."]))


@hook("model.post")
async def loud(answer: Message) -> Message:
    """Shout every answer the model gives."""
    return Message("assistant", answer.text.upper())


agent.hooks.attach(loud)

run = asyncio.run(agent.run("say hello"))
print(run.messages[-1].text)
```

```text output
HELLO THERE.
```

- `@hook("model.post")` says which of the eight moments it listens for.
- What `model.post` hands over is the model's reply.
- What the hook returns takes the reply's place. Return nothing and the reply
  stands.

## Async by design

The loop awaits your code, so your code has to be awaitable. A sync `invoke`,
`execute` or hook is refused up front, when you build the agent or attach the
hook. The fix is one line, `await asyncio.to_thread(...)` inside the async
method, and `@tool` writes even that for you.

<Note>
  An event listener is the exception. It is sync, because `emit()` never waits,
  and an `async def` there is refused. An async watcher takes
  [`stream()`](/events/streaming) instead.
</Note>

## ContractError

Forget the `async` on a hook and `attach` says so on the spot.

```text
no_rm must be async — write async def; sync work is one asyncio.to_thread line inside it

@hook("tool.pre")
async def no_rm(call: ToolCall):        # add a trailing `run` arg if you need it
    if call.name == "rm":
        return "denied"                 # the tool is skipped; this is its result

agent.hooks.attach(no_rm)               # untagged? attach(no_rm, "tool.pre")
```

Every `ContractError` reads like that. One line saying what is wrong, then the
code to type instead.
