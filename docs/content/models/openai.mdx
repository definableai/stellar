`models/openai/` speaks Chat Completions. Plenty of other vendors copied that
format, so the same class talks to them too.

This example needs a real key, so the docs test does not run it.

```python
import asyncio

from core import Agent
from models.openai import OpenAI

# OPENAI_API_KEY in the environment, or api_key="sk-..." here
agent = Agent(OpenAI("gpt-5.6-luna", temperature=0))
run = asyncio.run(agent.run("shout hello"))
print(run.messages[-1].text)
```

The address is `https://api.openai.com/v1` unless `base_url=` says otherwise.
Extra keywords are kept and put on the request, and yours win.

## The models in the box

| id | input size | output size | words |
| --- | --- | --- | --- |
| `gpt-5.6-sol` | 1,050,000 | 128,000 | the six below |
| `gpt-5.6-terra` | 1,050,000 | 128,000 | the six below |
| `gpt-5.6-luna` | 1,050,000 | 128,000 | the six below |
| `gpt-5.5` | 1,050,000 | 128,000 | the six below |

All four share one list of `image`, `tools`, `stream`, `tool_stream`, `json`
and `system`. There is no `document` and no `thinking`, because this API has
no shape for either. The [check](/models/profiles) refuses them before
anything is sent.

## What is different about this API

- **The reply has no block types.** Text arrives as a plain string, and tool
  calls arrive in a list beside it.
- **Tool arguments travel as text.** They are written out as JSON on the way
  out and read back on the way in. On the live stream they arrive a fragment
  at a time.
- **A tool result keeps its text only.** Pictures a tool returned follow in
  one user message right after, each captioned with the call id they belong
  to.
- **A part this API cannot say raises.** Anything but text or a picture stops
  the run. A profile word promised that part, so dropping it in silence would
  be a lie. The model's own past reply is the one exception.

## Other providers that copy this API

Three lines, in your own code.

<Tabs>
  <Tab title="Groq">

```python
from models.openai import OpenAI


class Groq(OpenAI):                     # in your code, not in models/
    url, env = "https://api.groq.com/openai/v1", "GROQ_API_KEY"
    PROFILES = {}                       # its own models, off its own docs
```

  </Tab>
  <Tab title="Ollama">

```python
from core import Profile
from models.openai import OpenAI


class Ollama(OpenAI):                   # a model on your laptop wants no key
    url, env = "http://localhost:11434/v1", None


ONE_POST = Profile("my-local-model", 32_000, 4_096,      # numbers off its docs
                   frozenset({"tools", "system"}))       # and no "stream"
model = Ollama("my-local-model", profile=ONE_POST)
```

  </Tab>
</Tabs>

The docs test runs neither one. Groq wants a key, and Ollama wants a model
running on your own machine.

Some look-alikes cannot hold a stream open. Give one a profile with no
`stream` word, and it sends one plain request instead.
