`models/anthropic/` talks to Claude. Name a model, and the key comes from you
or from `ANTHROPIC_API_KEY`.

This example needs a real key, so the docs test does not run it.

```python
import asyncio

from core import Agent
from models.anthropic import Anthropic

# ANTHROPIC_API_KEY in the environment, or api_key="sk-ant-..." here
agent = Agent(Anthropic("claude-sonnet-5", temperature=0))
run = asyncio.run(agent.run("shout hello"))
print(run.messages[-1].text)
```

Any extra keyword, like `temperature` or `max_tokens`, goes on the request. It
beats the default this provider would have used.

## The models in the box

| id | input size | output size | words |
| --- | --- | --- | --- |
| `claude-fable-5-1` | 1,000,000 | 128,000 | all eight |
| `claude-opus-5` | 1,000,000 | 128,000 | all eight |
| `claude-sonnet-5` | 1,000,000 | 128,000 | all eight |
| `claude-haiku-4-5` | 200,000 | 64,000 | all eight |

Every current Claude does everything, so all four share one list. An id
outside the table takes the longest row it starts with. See
[what a model can do](/models/profiles).

## What is different about this API

- **System messages travel on their own.** Every system
  [`Message`](/reference/types) is lifted out of the conversation and sent in
  its own field. What is left is the user and assistant turns.
- **A tool result can carry pictures.** Tool messages in a row merge into one
  user turn, each keeping its own id. A picture a tool returned rides inside
  the result it belongs to. See [what a tool may return](/tools/results).
- **Thinking blocks pass through both ways.** A block stellar does not know is
  kept whole, and goes back next turn exactly as it arrived.
- **The reply arrives live.** Text comes out a piece at a time. Every other
  block is held until it is finished, so a thinking block lands whole. Tool
  arguments ride the [event log](/events/streaming) as they arrive.

One last piece carries the cost, the name of who answered, and why it stopped.
