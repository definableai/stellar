A provider has two halves, and you test them differently. `encode` builds the
request and sends nothing, so you check what it built. `send` needs real
traffic, so you hand it real traffic with the socket taken out.

## Canned responses

`post` and `sse` are where tests plug in. Override `post` for the one-request
path, or `sse` for the live one. Do not reach for `httpx`, because everything
below those two methods is already tested.

The replies below have to be yours, so the docs test does not run this one.

```python
from core import Profile
from models.anthropic import DOES, Anthropic

# a proxy that cannot stream: the same model, one request at a time
ONCE = Profile("claude-sonnet-5", 1_000_000, 4096, DOES - {"stream"})


class Canned(Anthropic):
    """The real provider, with the request swapped for a list of replies."""

    def __init__(self, bodies) -> None:
        super().__init__("claude-sonnet-5", api_key="test", profile=ONCE)
        self.bodies, self.sent = list(bodies), []

    async def post(self, path, body) -> dict:
        self.sent.append(body)
        return self.bodies[len(self.sent) - 1]
```

Copy real replies out of the provider's docs, or off a live call. `Canned`
keeps every request it was handed in `self.sent`, which is how you check the
`encode` half afterwards.

## Conformance testing with `check_model`

`check_model(model)` runs your provider through the real loop three times.
First a plain reply with no tools. Then a reply asking for the built-in `echo`
tool. Then a reply after the tool result lands.

It checks the reply half.

- An assistant message with text comes back.
- The pieces add up, in order, to that text.
- A `meta` piece reached `message.meta`.
- A tool call arrives as a whole [`ToolCall`](/reference/types), with a dict of
  arguments.
- The tool message answers the right id, and the model stops after one round.

```python run
from core import FakeModel, Message, ToolCall
from core.conformance import check_model

ASKS = Message("assistant", "", [ToolCall("c1", "echo", {"text": "hi"})])
check_model(FakeModel(["ok", ASKS, "done"]))
print("passed")
```

```text output
passed
```

It cannot tell whether `encode` built a request your provider would accept, so
check that half yourself. `check_model` starts its own loop, so call it from
plain code and not from inside an `async def`.

## `FakeModel`

For everything that is not a provider, `FakeModel` reads its answers off a
list you wrote. It is a [`ProviderModel`](/models/provider) itself, so your
test goes down the same path a real model does.

```python run
import asyncio

from core import Agent, FakeModel

agent = Agent(FakeModel(["First answer.", "Second answer."]))

print(asyncio.run(agent.run("one")).messages[-1].text)
print(asyncio.run(agent.run("two")).messages[-1].text)
```

```text output
First answer.
Second answer.
```

- One entry per turn, in order. A string becomes an assistant message.
- A `Message` is taken apart into its pieces, then one piece per tool call,
  then one for its meta.
- Your list is copied, so the fixture survives the run.
- Ask for one more turn than you wrote and it raises `ContractError`, saying
  which reply it ran out after.
