---
title: Stopping runs and denying tool calls
description: Two signals and no third. Raise Stop to end a run, answer from tool.pre to skip a tool.
---

There are exactly two ways to steer a run from the outside. Everything else
is an ordinary error with ordinary consequences.

## Stopping a run with `Stop`

`raise Stop` from any hook or any tool ends the run cleanly. No error
reaches whoever called `agent.run(...)`, and the `Run` comes back holding
everything written down before the signal. Where the `Stop` came from
decides what that is.

```python run
import asyncio

from core import Agent, FakeModel, Message, Stop, ToolCall, hook, tool


@tool
def shout(word: str) -> str:
    """Shout a word."""
    return word.upper()


@hook("model.pre")
async def once(messages, run) -> None:
    """One model call per run, and no more."""
    if run.step > 1:
        raise Stop


asked = Message("assistant", "", [ToolCall("c1", "shout", {"word": "hi"})])
agent = Agent(FakeModel([asked, "never asked for"]), [shout])
agent.hooks.attach(once)
run = asyncio.run(agent.run("go"))
print([m.role for m in run.messages])
print(run.step)
```

```text output
['user', 'assistant', 'tool']
2
```

- The model was asked once, and the tool it wanted ran.
- The second turn stopped at `model.pre`, before the model was asked, so the
  second scripted reply was never spent.
- `run.step` reads 2 because the agent counts the turn up before your hooks
  run.

## `run.post` always fires

- It runs after a clean finish, after a `Stop`, and after a crash. That
  makes it the place to tidy up.
- A `Stop` raised inside `run.post` is ignored. It is too late to stop
  anything.
- Its event is always the last one written. That is why a
  [stream](/events/streaming) watching one run ends there, instead of
  hanging.

## Denying a tool call

Return a string or a `Message` from a `tool.pre` hook. Your agent skips the
tool and writes your answer down as the tool's result, stamped with the
call's id. The model reads it on the next turn and carries on.

```python run
import asyncio

from core import Agent, FakeModel, Message, ToolCall, hook


@hook("tool.pre")
async def cached(call: ToolCall) -> str | None:
    """Answer the weather from what we already know."""
    if call.name == "weather":
        return "sunny, 21 degrees"
    return None


asked = Message("assistant", "", [ToolCall("c1", "weather", {"city": "Paris"})])
agent = Agent(FakeModel([asked, "It is sunny in Paris."]))
agent.hooks.attach(cached)
run = asyncio.run(agent.run("what is the weather in Paris?"))
print(next(m.text for m in run.messages if m.role == "tool"))
print(run.messages[-1].text)
```

```text output
sunny, 21 degrees
It is sunny in Paris.
```

- That agent has no `weather` tool at all. The hook answered before the
  toolbox was ever looked at.
- The first hook to answer ends it, so the hooks behind it never hear about
  that call.
- There is no boolean to return and no third signal. A refusal is just the
  answer you would have got, written by you.

## Exception handling

| raised | what happens |
| --- | --- |
| `Stop`, from anywhere | the run ends cleanly and the `Run` comes back |
| any error inside a tool | it becomes that tool's answer, and the model gets another turn |

Everything else raises. A model that breaks, a hook that breaks, a
`ContractError` from a wrong return. `ContractError` raises even from inside
a tool, because a wiring mistake is not something to tell the model about.
