---
title: The four shipped cards
description: Steps, Budget, Permission and Log — four small files outside core that show what a rule card looks like.
---

Four cards ship with stellar, in `hooks/`. Three are hooks on the control
plane; one is a listener on [the data plane](/events/overview). None of them is
special: each is a file of under forty lines you can read, copy and change.

| card | plane | what it does |
| --- | --- | --- |
| `Steps(n)` | hook, `model.pre` | n model calls per run, then `Stop`. `Steps(3)` buys exactly three replies. |
| `Budget(max_tokens)` | hook, `model.post` | adds `input_tokens + output_tokens` from every reply's `meta["usage"]` into `run.extra["budget.tokens"]`. Past the limit it keeps the reply you already paid for, then stops. A reply with no usage costs nothing. |
| `Permission(deny, allow, ask)` | hook, `tool.pre` | the guard at the tool gate. `deny` wins; then an `allow` list settles it alone; only then does `ask=True` put the question to a human. |
| `Log(write=print)` | listener | one readable line per event: its name, and what it carried. |

<Note>
  Each card is a **factory**: calling it hands back the function, and the
  function is what you attach. Nothing is kept in the card — `Steps` counts on
  `run.step`, `Budget` totals into `run.extra` — so one card on the agent gives
  every run its own ration, its own purse, its own answer.
</Note>

## Steps

`Steps(n: int)` returns a [`model.pre`](/hooks/stages) hook. The loop counts
the turn up *before* the bell, so the card only has to compare:

```python
if run.step > n:
    raise Stop
```

`Steps(3)` buys exactly three replies. The fourth turn ends at `model.pre`, so
the finished run reads `run.step == 4` while the model was asked three times.
Attach one to the agent and every run gets its own ration, because the count
lives on the run.

## Budget

`Budget(max_tokens: int)` returns a [`model.post`](/hooks/stages) hook. It adds
`input_tokens` and `output_tokens` from the reply's `meta["usage"]` to the
running total in `run.extra["budget.tokens"]`, and past the limit it appends
the reply itself before raising `Stop` — you paid for that answer, so you keep
it.

The total lives in the run's own pocket, so it is per conversation and it rides
along in a [checkpoint](/patterns/checkpoint). A reply whose meta carries no
usage costs nothing: not every adapter counts, and a card that guessed would be
worse than one that does not.

## Permission

`Permission(deny=None, allow=None, ask=False)` returns a
[`tool.pre`](/hooks/stages) hook — the guard at the tool gate. It answers in
one order, and stops at the first answer:

<Steps>
  <Step title="deny wins">
    A call matching `deny` is refused: `denied: rm`. Nothing else is consulted.
  </Step>
  <Step title="an allow list settles it alone">
    If `allow` was given at all, a call on it passes and every other call is
    refused — `ask` never comes into it.
  </Step>
  <Step title="only then is a human asked">
    With no `allow` list and `ask=True`, the question goes out to whoever is
    listening.
  </Step>
</Steps>

Each of `deny` and `allow` is a set of names, or a predicate `(run, call)`
returning a bool — so a rule can read the arguments, not just the name:

```python
from hooks.permission import Permission

by_name = Permission(deny={"rm", "write"})
by_argument = Permission(deny=lambda run, call: call.args.get("path") == "/")
read_only = Permission(allow={"read", "search"})
```

`ask=True` asks through `extra["ui.ask"]`, an
`async (question, options=None) -> str` that you provide. The guard looks in
the run's pocket first and the agent's after, so one channel can serve every
conversation or each one can bring its own. The question it sends reads
`Allow shout({'word': 'hi'})?` with the options `["allow", "deny"]`.

<Warning>
  Anything but the exact string `"allow"` denies, and no channel at all denies
  too: with `ask=True` and no `ui.ask` anywhere, every call is refused with
  `denied: no ui.ask channel`. A guard with no voice says no.
</Warning>

## Log

`Log(write=print)` is not a hook. It returns a plain sync function for
`agent.events.listen`, and it writes one line per event — the event's name,
then what it carried:

```python
agent.events.listen(Log())                        # everything, to print
agent.events.listen(Log(lines.append), "tool")    # only the tool bells
agent.events.listen(Log(), run_id=run.id)         # one conversation of many
```

## All four on one agent

This runs as it stands — `FakeModel` needs no key and no network:

```python
import asyncio

from core import Agent, FakeModel, Message, ToolCall, tool
from hooks.budget import Budget
from hooks.logging import Log
from hooks.permission import Permission
from hooks.steps import Steps


@tool
def shout(word: str) -> str:
    """Shout a word."""
    return word.upper()


asked = Message("assistant", "", [ToolCall("c1", "shout", {"word": "hi"})])
agent = Agent(FakeModel([asked, "done"]), [shout])
agent.hooks.attach(Steps(8))
agent.hooks.attach(Budget(50_000))
agent.hooks.attach(Permission(deny={"rm"}))
agent.events.listen(Log())

asyncio.run(agent.run("shout hello"))
```

And this is what it prints, exactly:

```text
run.pre: shout hello
model.pre: 1 message
model.delta: <tool_call>
model.post: shout({'word': 'hi'})
tool.pre: shout({'word': 'hi'})
tool.post: HI
model.pre: 3 messages
model.delta: done
model.post: done
run.post: done
```

Ten events for a two-turn run, each emitted after its hooks agreed on the
payload. There is no `tool.delta` line because `shout` does not stream, and
`Permission` never speaks: it only refuses, and nothing asked for `rm`.
