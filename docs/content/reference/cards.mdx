Each one is a factory. It hands you a function, and the function is what you
attach. Nothing is kept inside the factory itself. `Steps` counts on `run.step`
and `Budget` adds up into `run.extra`. So one of these on the agent gives every
run its own count, its own total, and its own answer.

## Steps

```python
from hooks.steps import Steps

def Steps(n: int): ...
```

A limit on model calls. `Steps(3)` buys exactly three replies.

<ParamField path="n" type="int" required>
  How many model turns this run may take.
</ParamField>

<ResponseField name="hook" type="Callable">
  An async function tagged `model.pre`, taking two arguments, the conversation
  and the run. Attach it with `agent.hooks.attach(Steps(3))`.
</ResponseField>

The step number goes up before the `model.pre` stage, so the hook counts the
turn it is about to take. Past the limit it raises `Stop`, and the run ends
cleanly with everything written down so far.

## Budget

```python
from hooks.budget import Budget

def Budget(max_tokens: int): ...
```

Adds up what every reply cost, and ends the run once the total goes past the
limit.

<ParamField path="max_tokens" type="int" required>
  The ceiling for `input_tokens + output_tokens` across the whole run.
</ParamField>

<ResponseField name="hook" type="Callable">
  An async function tagged `model.post`, taking two arguments, the reply and the
  run.
</ResponseField>

It reads `answer.meta["usage"]` and adds up the two keys `input_tokens` and
`output_tokens`. The running total lives in `run.extra["budget.tokens"]`, so it
is per conversation and it rides along in the checkpoint. A reply with no usage
meta costs nothing, because not every adapter counts.

<Note>
  Past the limit it appends the reply to `run.messages` itself, before raising
  `Stop`. You paid for it, so you keep it. The loop's own append is the one
  being skipped, so the message lands exactly once.
</Note>

## Permission

```python
from hooks.permission import Permission

def Permission(deny=None, allow=None, ask: bool = False): ...
```

The guard on your tools. It answers before a tool runs.

<ParamField path="deny" type="set[str] | Callable[[Run, ToolCall], bool] | None" default="None">
  A set of tool names, or a test `(run, call) -> bool`. `None` matches nothing.
</ParamField>

<ParamField path="allow" type="set[str] | Callable[[Run, ToolCall], bool] | None" default="None">
  The same two shapes. If you pass one, it becomes the only way through.
</ParamField>

<ParamField path="ask" type="bool" default="False">
  `True` puts the question to a human, through `extra["ui.ask"]`.
</ParamField>

<ResponseField name="hook" type="Callable">
  An async function tagged `tool.pre`, taking two arguments, the call and the
  run. A returned `str` is the refusal. The tool never runs, and that string is
  its result for the model to read.
</ResponseField>

Which rule wins, first match first:

1. `deny` matches, so the call is denied with `f"denied: {call.name}"`.
2. `allow` is not `None`, so it settles the question alone. A match passes and
   anything else is denied. `ask` is never reached.
3. `ask=True`, so the human is asked. With nothing callable under
   `extra["ui.ask"]` the call is denied with `"denied: no ui.ask channel"`.
   Otherwise `ask(f"Allow {call.name}({call.args})?", ["allow", "deny"])` is
   awaited, and anything but `"allow"` denies.
4. Nothing matched, so the tool runs.

`extra["ui.ask"]` is looked up on the run first and the agent after. One channel
can serve every conversation, or each one can bring its own. It is a live
channel and never saved state. Keep it out of anything you checkpoint.

## Log

```python
from hooks.logging import Log

def Log(write=print): ...
```

Every event, as one line a person can read. It is a listener and not a hook, so
it changes nothing.

<ParamField path="write" type="Callable[[str], Any]" default="print">
  Where each line goes. `Log(lines.append)` collects them instead.
</ParamField>

<ResponseField name="listener" type="Callable[[Event], None]">
  A sync listener of one `Event`, for `agent.events.listen(...)`. It writes
  `f"{event.name}: {says(event.data)}"`.
</ResponseField>

`says` puts one payload in a few words. A `Message` is its text plus its tool
calls. A `ToolCall` is `name(args)`. A text `Part` is its text, and any other
`Part` is its type in angle brackets. A list is `"3 messages"`, and `None` is
nothing at all.

```python
agent.events.listen(Log())                        # everything, to print
agent.events.listen(Log(lines.append), "tool")    # only the tool events
agent.events.listen(Log(), run_id=run.id)         # one conversation of many
```
