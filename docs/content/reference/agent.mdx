You build one `Agent` and then give it jobs. Each job is a `Run` with its own
conversation. Both live in `core/agent.py`. The loop's own `run` and `check`
live in `core/loop.py`, and all four come out of `core`.

## Agent

```python
from core import Agent

Agent(model, tools=(), hooks=Hooks(), events=Events(), extra={})
```

Everything your agent needs, in one object. It is a dataclass, so you can swap
any part by assignment, even while a run is going. `check()` reads the whole
agent again at the top of every step.

<ParamField path="model" type="Model" required>
  The model the agent asks. Every run of this agent asks this one.
</ParamField>

<ParamField path="tools" type="Iterable[Tool] | Mapping[str, Tool]" default="()">
  The tools it can use. Hand it a list or a dict. A list is keyed by each tool's
  `name` while the agent is built. After that it is always the dict.
</ParamField>

<ParamField path="hooks" type="Hooks" default="Hooks()">
  The rules. Every agent gets its own set, and each run chains onto it.
</ParamField>

<ParamField path="events" type="Events" default="Events()">
  The event log. Every agent gets its own, and every run it starts writes there.
</ParamField>

<ParamField path="extra" type="dict[str, Any]" default="{}">
  A dict for anything else, shared by every run. Use names with a dot in them,
  like `extra["ui.ask"]`.
</ParamField>

<ResponseField name="tools" type="Mapping[str, Tool]">
  A dict of name to tool once the agent is built, whichever of the two shapes
  you handed in.
</ResponseField>

<Note>
  `Agent` has one method, `run()`. There is never a second one.
</Note>

Raises `ContractError` when two tools answer to one name, and whatever
[`check()`](/reference/agent#check) refuses. Both happen while you build the
agent, not at the first step.

### Agent.run()

```python
from core import Agent

async def run(
    self,
    prompt: str | Message | None = None,
    *,
    messages: list[Message] | None = None,
    run_id: str | None = None,
) -> Run: ...
```

Give the agent a job. It builds the `Run` and hands it to `core.loop.run`.

<ParamField path="prompt" type="str | Message | None" default="None">
  A `str` becomes a user `Message`. A `Message` is taken as it is, pictures and
  all. It goes after `messages=`. Pass `None` only if `messages=` says enough.
</ParamField>

<ParamField path="messages" type="list[Message] | None" default="None">
  The conversation to start from. It is copied, so your own list is left alone.
</ParamField>

<ParamField path="run_id" type="str | None" default="None">
  Pass an old id to carry that run on, and to find its events. `None` makes a
  fresh `uuid4().hex`.
</ParamField>

<ResponseField name="run" type="Run">
  The `Run` the loop filled in. It holds the conversation, the step count, and
  the id.
</ResponseField>

Raises `ContractError("run needs a prompt or messages")` when both are empty.

## Run

```python
from core import Run

Run(agent, id, messages, step=0, hooks=Hooks(), extra={})
```

One job. It has its own conversation (`run.messages`), its own id, and its own
hooks. `Agent.run()` builds one for you. Build one yourself only to drive
`core.loop.run` by hand.

<ParamField path="agent" type="Agent" required>
  The agent behind this run. It is left out of the checkpoint.
</ParamField>

<ParamField path="id" type="str" required>
  Hex, made fresh per run, or the one you handed in to carry a run on.
</ParamField>

<ParamField path="messages" type="list[Message]" required>
  The conversation, in order. The loop appends to it, and a `model.pre` hook can
  replace it.
</ParamField>

<ParamField path="step" type="int" default="0">
  Model turns taken. The loop counts up before each `invoke`. A `model.pre` hook
  already sees the turn it is about to take.
</ParamField>

<ParamField path="hooks" type="Hooks" default="Hooks()">
  Rules for this run alone. No other run sees them.
</ParamField>

<ParamField path="extra" type="dict[str, Any]" default="{}">
  A dict for this run alone. `Budget` keeps its total here.
</ParamField>

<ResponseField name="hooks.parent" type="Hooks">
  When the run is built, its hooks chain onto `agent.hooks` unless a parent was
  already set. One stage then runs both sets.
</ResponseField>

### Run.emit()

```python
from core import Run

def emit(self, name: str, data: Any = None, source: str | None = None) -> Event: ...
```

Write one event, stamped with this run's id. It never blocks and never raises.

<ParamField path="name" type="str" required>
  A dotted name. The loop uses the eight stage names. You can use anything.
</ParamField>

<ParamField path="data" type="Any" default="None">
  Whatever should go with it, stored as it is.
</ParamField>

<ParamField path="source" type="str | None" default="None">
  Who is speaking. `"loop"`, a tool's name, or yours.
</ParamField>

<ResponseField name="event" type="Event">
  The `Event`, already numbered and already in `agent.events.log`.
</ResponseField>

### Run.\_\_getstate\_\_()

```python
from core import Run

def __getstate__(self) -> dict[str, Any]: ...
```

What a checkpoint keeps. `id`, `messages`, `step`, `extra`, and nothing else.
The agent, its hooks and its event log are dropped, because you build those in
code again. Then `agent.run(messages=..., run_id=...)` picks the conversation
back up.

## The loop's run()

```python
from core import run

async def run(run: Run) -> Run: ...
```

The loop itself, which `Agent.run()` calls. First it runs the `run.pre` hooks on
the last message. Then it repeats five things. `check(run.agent)`, `step += 1`,
the `model.pre` hooks, the model's `invoke`, the `model.post` hooks. The answer
goes into the conversation, and if it asked for tools, `act()` runs them. The
loop ends when an answer asks for no tools.

<ParamField path="run" type="Run" required>
  Arrives with at least one message. The `run.pre` hooks run on the last one.
</ParamField>

<ResponseField name="run" type="Run">
  The same object, with the conversation filled in.
</ResponseField>

`Stop` from any hook or tool ends the loop cleanly. The `run.post` hooks run
either way, because they sit in a `finally`. The `run.post` event is written
last, and that is what ends a stream. An `invoke` that hands back something
other than a `Message` raises `ContractError`.

Three helpers in `core.loop` do the work a hook author will meet.

- `coerce(result, call) -> Message` turns whatever a tool returned into one tool
  message. See [what a tool returns](/tools/results).
- `use(run, tool, call) -> Message | Any` runs one tool. An async generator
  streams, and every `Part` runs the `tool.delta` hooks.
- `act(run, answer) -> None` runs everything one answer asked for, batch by
  batch. See [parallel tools](/tools/parallel).

## check()

```python
from core import check

def check(agent: Agent) -> None: ...
```

Reads the agent and says what you wired wrong, before it runs. It runs when you
build the agent, and again at the top of every step. A part you swapped mid-run
is checked too.

<ParamField path="agent" type="Agent" required>
  The whole agent. Its model, and every tool it holds.
</ParamField>

Raises `ContractError`. What it refuses, in this order:

- a model whose own class writes no `invoke`
- an `invoke` that is not async
- an `agent.tools` that is not a dict
- a tool with no `name`
- a tool filed under a key that is not its name
- a tool whose `parameters` is not a dict
- a tool that writes no `execute`
- an `execute` that is not async

Each message names the problem and then prints the code to type instead.

It never asks what your class inherits from. Any object whose own class writes
an async `invoke(run)` is a model.

See also: [the loop](/concepts/loop) and [saving a run](/patterns/checkpoint).
