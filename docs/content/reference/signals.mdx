Two exceptions, both in `core/contracts.py`, both out of `core`. There are no
others. The loop catches exactly two things, a `Stop` and a tool's own
exception, and everything else is raised.

## ContractError

```python
from core import ContractError

class ContractError(Exception): ...
```

You implemented it wrong. The message says what to type instead.

Most of them are built by `core.contracts.wrong(kind, problem)`, which glues the
complaint to a skeleton. The skeletons are in `core.contracts.SKELETONS`, keyed
`model`, `provider`, `tool` or `hook`. So the text is one sentence naming what
is wrong, a blank line, and then the code to copy.

```text
tool 'shout'.execute must be async — sync code is one asyncio.to_thread line inside it

class MyTool(Tool):
    name = "shout"
    description = "Shout a word."
    parameters = {"type": "object", "properties": {"word": {"type": "string"}}}

    async def execute(self, run, word):
        return word.upper()

# or decorate a plain function with @tool — sync, async, or async generator
```

Where each one comes from:

| raised by | when |
| --- | --- |
| `Agent.run()` | no prompt and no messages |
| `Agent.__post_init__` | two tools answering to one name |
| `check()` | a model that is not one, a sync `invoke`, tools that are not a dict, a tool with no name or the wrong key or no `execute` or a sync one |
| `Hooks.attach()` | a hook that is not async, names no stage, names one that is not a stage, or takes the wrong number of arguments |
| `@hook` | a misspelled stage, at decoration time |
| `Hooks.fire()` | a hook that returned the wrong type |
| `core.loop.run` | an `invoke` that handed back something that is not a `Message` |
| `ProviderModel.invoke()` | a `send` that yielded something that is not a `Part` |
| `fold()` | a `tool_call` part that is not carrying a whole `ToolCall` |
| `@tool` | a function with `*args` or `**kwargs`, or with no `__name__` |
| `Events.listen()` | an `async def` listener |
| `FakeModel.send()` | the script ran out |
| `core.conformance` | an exchange that did not add up |

<Warning>
  Nothing catches it. A tool that raises has its exception turned into the
  tool's result for the model to read, as `error: ValueError: nope`. A
  `ContractError` from a tool is raised instead. A broken contract is a bug to
  fix, not an answer to send.
</Warning>

## Stop

```python
from core import Stop

class Stop(Exception): ...
```

End the run cleanly. Raise it from any hook or any tool. No traceback reaches
the caller. You get the `Run` back, holding everything written down so far.

Who raises it. Your own code, and two of the hooks stellar ships.
[`Steps(n)`](/reference/cards) stops the run once it has taken its `n` turns.
[`Budget(max_tokens)`](/reference/cards) stops it once the total goes past the
limit.

Who catches it:

- `core.loop.run`, in one `except Stop: pass` around the whole loop.
- `core.loop.run` again, around the `run.post` hooks alone, where a `Stop` is
  dropped because it is too late to stop anything.
- `core.loop._attempt` raises it on rather than turning it into a tool result.
  `act()` raises it only once the whole batch has finished, first in call order,
  so nothing is cancelled halfway through.

<Note>
  The `run.post` hooks always run. After a clean finish, after a `Stop`, and
  after a crash, because they sit in a `finally`. Any other exception out of
  `run.post` propagates the ordinary way, with whatever was already in flight
  attached as `__context__`. The `run.post` event is written from an inner
  `finally` even then, so a stream still ends.
</Note>

See also: [stopping a run](/hooks/stopping) and
[the contracts](/concepts/contracts).
