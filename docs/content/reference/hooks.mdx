The rules your agent checks, in `core/contracts.py`. A hook is an async function
filed under one or more of the eight stage names. It runs inline, and what it
returns replaces the payload.

## Hooks

```python
from core import Hooks

class Hooks:
    def __init__(self, parent: Hooks | None = None) -> None: ...
```

Where the hooks are kept, filed by stage. Attach order is call order. One set
can chain to a parent, whose hooks run first. A `Run`'s hooks chain onto its
`Agent`'s when the run is built, so one stage runs both sets.

<ParamField path="parent" type="Hooks | None" default="None">
  Runs first. A `tool.pre` skip up there means this set never hears that stage.
</ParamField>

<ResponseField name="parent" type="Hooks | None">
  The set above this one. `Run.__post_init__` sets it to `agent.hooks` unless
  one was already there.
</ResponseField>

<ResponseField name="fns" type="dict[str, list[tuple[Any, bool]]]">
  One list per stage name, in attach order. Each entry holds the function and
  whether it left room for the run after its payload.
</ResponseField>

<Warning>
  Swap hooks with `attach` and `detach`, not by giving `agent.hooks` a new value
  mid-run. The parent is bound when the run is built. A run already going keeps
  pointing at the set it was given.
</Warning>

### Hooks.attach()

```python
def attach(self, fn: Callable[..., Any], *stages: str) -> Hooks: ...
```

File one function under the stages named here, or the ones `@hook` tagged. A
stage named at attach beats the tag, so an untagged function works too.

<ParamField path="fn" type="Callable[..., Any]" required>
  Filed as it is, and left a function. One function may sit on several stages.
</ParamField>

<ParamField path="stages" type="*str">
  The stages to file it under, one or more of the eight names. Leave them out
  and `fn.stages` is read instead.
</ParamField>

<ResponseField name="hooks" type="Hooks">
  `self`, so attaches chain.
</ResponseField>

Raises `ContractError` at attach, not mid-run. It refuses a function that:

- names no stage
- names something that is not a stage
- is not `async def`
- takes the wrong number of arguments

A hook takes exactly what its stage hands over, or one more. That one is the
run.

### Hooks.detach()

```python
def detach(self, fn: Callable[..., Any]) -> Hooks: ...
```

Unfile it, from every stage it listened to. Matched by identity, so pass the
same object you attached. Hands back `self`.

### Hooks.fire()

```python
async def fire(self, stage: str, run: Run, *payload: Any) -> tuple[Any, ...] | str | Message: ...
```

Run one stage. The parent's hooks go first, then these, in attach order. The
loop calls this. You call it only when you drive the loop yourself.

<ParamField path="stage" type="str" required>
  One of the eight names. Its hooks are the ones that run.
</ParamField>

<ParamField path="run" type="Run" required>
  Handed over only to a hook that left room for it after the payload.
</ParamField>

<ParamField path="payload" type="*Any">
  The stage's arguments. `PAYLOAD` says the shape it wants.
</ParamField>

<ResponseField name="payload" type="tuple[Any, ...] | str | Message">
  The payload back as a tuple. Two overloads narrow it. At `tool.pre` a `str` or
  a `Message` may come back instead. At every other stage the tuple is all there
  is.
</ResponseField>

What a hook returns is what the next one hears, and `None` leaves the payload
alone. Only the last slot is replaced. That is why a `tool.post` hook returning
a `Message` changes the result and not the call.

At `tool.pre` the first hook that answers with a `str` or a `Message` ends the
stage. The tool is skipped and that answer is its result. A skip in the parent
set means these hooks never run at all. A hook attached while a stage is running
waits for the next one.

Raises `ContractError` naming your function, the stage, and what to return
instead, when a hook hands back the wrong type.

### fold()

```python
from core.contracts import fold

def fold(message: Message, part: Part) -> None: ...
```

Joins one streamed `Part` into the growing `Message`, in place. This is the
protocol a `model.delta` or `tool.delta` hook stands in front of. `text` joins
onto the last text part. `tool_call` appends its whole `ToolCall`. `meta`
merges into `message.meta`, later keys winning. Every other type lands in
`content` untouched. A `tool_call` part carrying anything but a `ToolCall`
raises `ContractError`.

## @hook

```python
from core import hook

def hook(*stages: str) -> Callable[[Any], Any]: ...
```

Tag a function with the stages it listens for. It stays a function. The tag
writes `fn.stages` and hands the function straight back, so `attach(fn)` then
needs no stage names.

<ParamField path="stages" type="*str" required>
  The stages to listen for, one or more of the eight names.
</ParamField>

Raises `ContractError` right there, at decoration time, if a stage is
misspelled.

```python run
from core import ToolCall, hook


@hook("tool.pre")
async def no_rm(call: ToolCall):
    if call.name == "rm":
        return "denied"


print(no_rm.stages)
```

```text output
('tool.pre',)
```

## STAGES

```python
from core import STAGES
```

The eight stages, in the order they run, as a `tuple[str, ...]`. They are
`run.pre`, `model.pre`, `model.delta`, `model.post`, `tool.pre`, `tool.delta`,
`tool.post` and `run.post`. A hook name and an event name are one word. These
are also the eight names the loop writes to the event log.

## PAYLOAD

```python
from core.contracts import PAYLOAD
```

What each stage hands its hooks, as `dict[str, tuple[type, ...]]`. `attach`
reads it to see how many arguments your hook takes. `fire` reads its last entry
to check what a hook returned.

| stage | payload | what a return replaces |
| --- | --- | --- |
| `run.pre` | `Message`, the last message, once, before the first turn | that message |
| `model.pre` | `list`, the conversation, before every model call | `run.messages`, for good |
| `model.delta` | `Part`, one streamed piece, before it is joined | the `Part`, and the new one is joined |
| `model.post` | `Message`, the reply, after every model call | the reply that gets written down |
| `tool.pre` | `ToolCall`, before every tool | a `ToolCall` runs instead. A `str` or `Message` skips the tool and is its result |
| `tool.delta` | `Part`, one yielded piece, before it is joined | the `Part`, and the new one is joined |
| `tool.post` | `ToolCall, Message`, the call and its result | the result, the last slot only |
| `run.post` | `Message`, the last message, once, at the very end | nothing, this stage is the end |

<Note>
  The count is taken once, at attach. A hook that does not fit its stage is
  refused there, not mid-run. Positional parameters are counted, so a
  `tool.post` hook takes two, or three with the run.
</Note>
