---
title: A class is a tool
description: Subclass Tool when you want your own name, your own schema, or something to hold on to.
---

`@tool` reads your function and gives you no say in what it read. Subclass
`Tool` and every part is yours.

Reach for a class when the tool has to **hold on to something**. The object
lives as long as the agent. An open connection, a cache, or a count is still
there on the next call.

## The four things you set

| you set | what it is |
| --- | --- |
| `name` | what the model asks for. An empty one fails the check before the first turn |
| `description` | the sentence the model reads when it decides whether to call you |
| `parameters` | JSON Schema, sent as it is. The default is an object with no arguments |
| `parallel` | `True` lets this tool run beside other parallel ones. See [running tools at the same time](/tools/parallel) |

`execute` is the one method and it is always async. It takes the run first,
then the arguments your schema promised, by name.

Give the agent an instance, not the class.

## Try it

```python run
import asyncio

from core import Agent, FakeModel, Message, Tool, ToolCall


class Shout(Tool):
    name = "shout"
    description = "Shout a word."
    parameters = {"type": "object", "properties": {"word": {"type": "string"}}}

    async def execute(self, run, word) -> str:
        return word.upper()


asked = Message("assistant", "", [ToolCall("c1", "shout", {"word": "hi"})])
run = asyncio.run(Agent(FakeModel([asked, "done"]), [Shout()]).run("shout hi"))
print(next(m.text for m in run.messages if m.role == "tool"))
```

```text output
HI
```

- Write `parameters` on your own class. The one on the base class is shared
  by every tool that does not replace it.
- Slow work goes inside `execute`, in one line, like
  `await asyncio.to_thread(str.upper, word)`.
- A plain `def execute` is refused when you build the agent, and the message
  tells you to do exactly that.

## Streaming

Write `execute` as an async generator and the tool streams. Each `Part` it
yields goes out the moment it happens, and the pieces join into one message
at the end.

```python run
import asyncio

from core import Agent, FakeModel, Message, Part, Tool, ToolCall


class Teller(Tool):
    name = "tell"
    description = "Tell a story, a piece at a time."
    parameters = {"type": "object", "properties": {}}

    async def execute(self, run):
        yield Part("text", "once ")
        yield Part("text", "upon ")
        yield Part("text", "a time")


pieces = []
asked = Message("assistant", "", [ToolCall("c1", "tell")])
agent = Agent(FakeModel([asked, "done"]), [Teller()])
agent.events.listen(lambda event: pieces.append(event.data.data), "tool.delta")
run = asyncio.run(agent.run("tell me a story"))
print(pieces)
print(next(m.text for m in run.messages if m.role == "tool"))
```

```text output
['once ', 'upon ', 'a time']
once upon a time
```

- Three pieces went out one at a time. Anyone watching saw them arrive.
- The model reads one message, `once upon a time`.
- A tool that breaks halfway sends the error instead, and the pieces it had
  already yielded are dropped.

## One instance for every job

<Warning>
  One tool object is shared by every job that agent runs, and two jobs can
  run at once. Anything that belongs to one conversation goes in
  `run.extra`, not on the tool.
</Warning>
