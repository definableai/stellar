---
title: A function is a tool
description: Put @tool on a plain Python function, and your agent can call it.
---

A tool is one thing your agent can do. Write an ordinary Python function,
put `@tool` on top of it, and you have one.

## What @tool reads

The tool's **name** is the function's name. Its **description** is the
docstring, which is the sentence the model reads when it decides whether to
call you. Its arguments come from the signature. An argument with a default
is optional, and one without is required.

## Try it

This needs no API key. `FakeModel` plays the model and says what you told
it to say. Here it asks for `shout`, then answers.

```python run
import asyncio
import json
from typing import Annotated

from core import Agent, FakeModel, Message, ToolCall, tool


@tool
def shout(word: Annotated[str, "the word to shout"], times: int = 1) -> str:
    """Shout a word."""
    return " ".join([word.upper()] * times)


print(shout.name, "-", shout.description)
print(json.dumps(shout.parameters, indent=2))

asked = Message("assistant", "", [ToolCall("c1", "shout", {"word": "hi", "times": 2})])
run = asyncio.run(Agent(FakeModel([asked, "done"]), [shout]).run("shout hi twice"))
print(next(m.text for m in run.messages if m.role == "tool"))
```

```text output
shout - Shout a word.
{
  "type": "object",
  "properties": {
    "word": {
      "type": "string",
      "description": "the word to shout"
    },
    "times": {
      "type": "integer"
    }
  },
  "required": [
    "word"
  ]
}
HI HI
```

- `shout.parameters` is exactly what the model is offered. Nothing else
  about your function is sent.
- An `Annotated` note becomes that argument's description. It is the one
  place to tell the model what an argument means.
- The tool ran, and `HI HI` went back into the conversation for the model
  to read.

## Which type hints the model understands

Six of them have a name. Anything else has none, and the model may then
send what it likes.

| you write | the model sees |
| --- | --- |
| `str` | `string` |
| `int` | `integer` |
| `float` | `number` |
| `bool` | `boolean` |
| `list`, `list[str]` | `array` |
| `dict`, `dict[str, int]` | `object` |
| anything else, or no hint | no type at all |

## Sync, async, or streaming

`@tool` looks at the kind of function you wrote.

- An **ordinary function** runs in a thread, so slow work does not hold up
  the rest of the program.
- An **async function** is awaited.
- An **async generator** streams. Each `Part` it yields goes out the moment
  it happens, and the pieces join into one message at the end.

## Ask for the run

Name the first argument `run` and the agent fills that one in for you. The
model never sees it, so it is not in the schema.

```python
from core import tool


@tool
def so_far(run) -> int:
    """How many messages the conversation holds."""
    return len(run.messages)
```

## One option only

`@tool` takes one keyword and no others. `@tool(parallel=True)` lets this
tool run beside other parallel ones. [Running tools at the same
time](/tools/parallel) says when to use it.

For a different name, description or schema, write a
[class](/tools/classes) instead. That is what the class is for.

<Note>
  `@tool` cannot read `*args` or `**kwargs`. A function with either raises
  `ContractError` the moment its file is imported, not halfway through a
  run.
</Note>
