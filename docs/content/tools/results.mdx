---
title: What a tool can return
description: Anything at all. Whatever comes back is shaped into the one message the model reads.
---

A tool owes you no return type. Whatever it hands back becomes one message,
stamped with the call's id. That message is the next line in the
conversation.

## The seven shapes

| you return | the model gets |
| --- | --- |
| a `str` | that text |
| a `Part` | that one piece, so a picture with no words |
| a list of `Part`s | all of them in order, so words and a picture together |
| a `Message` | your message, with its role set to `tool`, and an id if it had none |
| a `dict`, a list, a number, `True` | the JSON for it |
| `None` | `null`, which is the JSON for nothing |
| anything JSON cannot hold | the `str()` of it |

An empty list is still JSON, so it arrives as `[]` and not as nothing.

## Try it

Three tools in one turn. One returns a dict, one returns a picture, and one
breaks.

```python run
import asyncio

from core import Agent, FakeModel, Message, Part, ToolCall, tool


@tool
def bag() -> dict:
    """Hand back a dict."""
    return {"n": 1}


@tool
def pic() -> Part:
    """Hand back a picture."""
    return Part("image", {"url": "https://example.com/a.png"})


@tool
def boom() -> str:
    """Always breaks."""
    raise ValueError("nope")


asked = Message("assistant", "", [ToolCall("c1", "bag"), ToolCall("c2", "pic"),
                                  ToolCall("c3", "boom")])
run = asyncio.run(Agent(FakeModel([asked, "done"]), [bag, pic, boom]).run("go"))
for message in run.messages:
    if message.role == "tool":
        for part in message.content:
            print(part.type, part.data)
```

```text output
text {"n": 1}
image {'url': 'https://example.com/a.png'}
text error: ValueError: nope
```

- The dict came back as JSON text. The model reads `{"n": 1}`.
- The picture stayed a picture. Nothing turned it into words.
- The tool that broke did not break the run. Its mistake is just another
  answer.

A streaming tool returns nothing at all. Its result is the pieces it
yielded, joined into one message.

## When a tool fails

| what happened | what the model reads |
| --- | --- |
| your tool raised | `error: ValueError: nope` |
| the model asked for a tool you do not have | `error: unknown tool: ghost` |
| the model's arguments were not valid JSON | `error: tool arguments were not valid JSON: {oops` |

The model gets another turn and can try again.

<Note>
  Two exceptions are never turned into an answer. `Stop` ends the run, and
  `ContractError` raises, because a wiring mistake is not something to tell
  the model about. See [stop a run, skip a tool](/hooks/stopping).
</Note>

Your answers are checked before they are sent. A picture handed to a model
that cannot read pictures raises `Unsupported` at no cost, before anything
leaves your machine. [Profiles](/models/profiles) has that check.
